# logs/ — логи игры

Сырые `xray_*.log` — временные: по несколько мегабайт, с локальными путями и именем пользователя Windows. В git и в индекс Cursor не попадают. Исключение — `logs/samples/`, синтетические примеры для тестов инструментов.

Постоянная база — карточки в `logs/cards/`. Одна карточка на разбор, имя `YYYY-MM-DD_<источник>.md` (при совпадении — суффикс `-2`). Их можно коммитить и искать. Одноразовая копия текущего прогона — `logs/card.md`: каждый запуск затирает предыдущий, в индекс Cursor не входит.

```bash
python3 tools/xraylog.py logs/xray_ivan.log --out logs/card.md --archive
```

`--archive` пишет карточку в `logs/cards/` и печатает путь. Без флага поведение прежнее: stdout или `--out`. Класс «вылета в логе нет» (чистая сессия) по умолчанию **не** архивируется — нужен явный `--archive-clean`, иначе база снова забьётся пустыми карточками. При полном совпадении сигнатуры с уже лежащей карточкой `xraylog` печатает предупреждение в stderr, но не блокирует запись — решение за человеком.

Дальше работаем по карточке — см. [`../docs/plans/crash.md`](../docs/plans/crash.md).

## Когда архивировать

Карточку кладут в `logs/cards/` только если выполняется **хотя бы одно** из трёх условий. Все три равноправны. Перед `--archive` условие называют вслух (какое именно); если ни одно не выполняется — `--archive` не запускают.

1. **Новая сигнатура.** Класса ошибки (FATAL Description / уникальный набор нефатальных групп с их кадрами) нет ни в одной карточке `logs/cards/`, ни в одной записи `docs/issues.md`. Проверка: grep по фрагменту Description или по culprit+триггеру группы; для журнала — `grep -F '<фрагмент>' docs/issues.md`.
2. **Значимая динамика.** Тот же мод или тот же тестер, что в уже лежащей карточке, но после правки заметно изменились число или состав групп (другие culprit'ы, другие триггеры, другой счётчик групп в классе). «Чуть другие warning'и при тех же группах» — не динамика.
3. **Точка отсчёта.** Чистая сессия (или сессия сразу после крупного изменения пакета фиксов), которую дальше будут сравнивать с новыми логами того же тестера/мода. Для класса «вылета в логе нет» — только с `--archive-clean`, и только если это именно baseline, а не «просто сессия без вылета».

## Когда не архивировать

Любое из ниже — достаточное основание **не** писать в `logs/cards/`:

- **Повтор известной сигнатуры без изменений.** Та же FATAL Description или тот же набор нефатальных групп (состав и смысл), уже есть карточка и/или запись в `docs/issues.md`, динамики после правки нет.
- **Чужая сборка.** По шапке/путям в логе установка не наша Anthology 2.1 (например каталог вроде `c:/dreams of hell/`). Имя `Anomaly*.exe` само по себе ничего не доказывает: путь установки у тестеров разный, единого маркера «наша папка» в логе нет — решение глазами по полному пути в SymInit / `-----loading` / обрезанных путях скриптов, не автоматом.
- **Дубль той же сессии.** Тот же файл лога или копия (`xray_foo (1).log`) уже разобрана; повторный прогон `xraylog` не создаёт новую ценность.
- Черновики вне схемы имён (`nikit_card.txt`, вывод через `>` / `Out-File`) в `logs/cards/` не кладут — только `YYYY-MM-DD_<источник>.md` через `--archive` / `--out`.

Ротация сырых логов оставляет N самых свежих `logs/*.log` (по умолчанию 3), `logs/samples/` не трогает:

```bash
python3 tools/prune_logs.py --dry-run
python3 tools/prune_logs.py --yes
python3 tools/prune_logs.py --yes --keep 5
```

Без `--yes` ничего не удаляется.

Полезные режимы:

```bash
python3 tools/xraylog.py logs/xray_ivan.log --warnings-only   # только предупреждения, без вылета
python3 tools/xraylog.py logs/xray_ivan.log --errors-only     # только нефатальные STACK TRACEBACK
python3 tools/xraylog.py logs/xray_ivan.log --context 80      # больше строк перед падением
python3 tools/xraylog.py logs/xray_ivan.log --json            # машиночитаемо
```
