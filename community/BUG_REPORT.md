# Отчёт о проблеме

Шаблон для тестеров бета-сборок фиксов / аддонов. Минимум полей — по практике сообщества (см. readme [xlibs](https://www.moddb.com/addons/xlibs-1001) на ModDB). Без этих данных разбор обычно упирается в «не воспроизводится» или «не наш мод».

## Поля

| Поле | Что писать |
| --- | --- |
| Кратко | Одна строка: что сломалось |
| Шаги | Точные шаги воспроизведения с нуля |
| Сейв | Новая игра **или** имя сейва (как в списке загрузок) |
| Ожидалось | Что должно было произойти |
| Получилось | Что произошло вместо этого |
| Сборка | Версия Anthology (например 2.1) |
| Движок | Modded Exes / build из шапки `xray_*.log` (`'xrCore' build …`) |
| Порядок | Порядок загрузки модов в MO2 (сверху вниз или скрин списка слева) |
| modlist.txt | Файл из профиля MO2: `profiles/<профиль>/modlist.txt` |
| Лог | Полный `xray_<user>.log` сессии с проблемой (не фрагмент) |

Скриншот ошибки или «вылета» **не заменяет** лог и modlist.

## Почему нужен полный лог, а не скриншот

При сотнях модов и оверрайдов скрин FATAL / Lua-попапа показывает только симптом. Полный `xray_*.log` — единственный способ увидеть load order конфигов, presence-строки аддонов, цепочку ошибок до вылета и то, **был ли замешан наш аддон** (секция «мои моды» / строки с тегом фикса). Без лога нельзя отличить наш баг от чужого мода, порчи сейва или конфликта двух паков на один файл.

## Почему нужен modlist.txt

Список слева в MO2 и «я поставил ваш фикс» недостаточны: в профиле часто одновременно лежат ZIP старой версии, копия в `[DBG] Kristiano Fixes ALL IN ONE` и актуальный слот. Конфликт двух версий одного фикса виден только по `modlist.txt` (плюс/минус у каждой строки). Уже был случай: две версии `fix_indeikam_breeding` в одном профиле — без modlist это не отловить.

## Куда приложить

В Discord / тикет: заполненные поля + два файла (`modlist.txt`, полный `xray_*.log`). Лог лучше zip’ом, если больше лимита вложения.
