# План: новый аддон

Для случая «хочу новую механику». Правило: [`.cursor/rules/workflow-addon.mdc`](../../.cursor/rules/workflow-addon.mdc).

Ключевая идея: главный риск здесь не баг, а **изобретённая архитектура**. Агент охотно пишет собственный менеджер состояния и собственный планировщик там, где в Anomaly уже есть штатный механизм. Поэтому этап 1 — не про твою фичу, а про то, как похожее уже сделано в сборке.

## Этап 1. Разбор существующей реализации

```
Это новый аддон, веди по workflow-addon. Этап 1, файлов не создавай.

Что хочу: <механика в 2-3 предложениях, с точки зрения игрока>

Найди в reference/ и в аддонах сборки 1-3 примера, где уже сделано
что-то похожее. Дай пути и краткое описание подхода.
Если такая механика уже есть — скажи об этом прямо.
```

## Этап 2. План

```
Этап 2. Дай таблицу: файл -> создаётся/патчится -> назначение одной строкой.
Отдельно:
- движковые функции и callback'и (каждую проверь через tools/refindex.py);
- что сохраняется в сейв и как читается на старом сейве;
- какие настройки уйдут в MCM;
- зависимости от других модов сборки.
Кода не пиши.
```

Здесь режь объём. Если в плане пятнадцать файлов — почти наверняка это не одна фича, а платформа. Оставь минимальный работающий срез, остальное в «версию 1.1».

## Этап 3. Каркас

```bash
python3 tools/new_addon.py <mod_id> --title "Читаемое имя"
```

Создаётся `addon/<mod_id>/` с `meta.ini`, `CHANGELOG.md`, скриптом логики, `<mod_id>_mcm.script` и примером DLTX-патча. Лишнее удаляем сразу.

## Этап 4. Реализация

```
Этап 4. Реализуй по утверждённому плану.
MCM-настройки сразу, не отдельным шагом.
Тяжёлые операции — через CreateTimeEvent, не в actor_on_update.
Каждую движковую функцию, которой нет в reference/, помечай -- UNVERIFIED.
```

## Этап 5. Самопроверка

```bash
python3 tools/lint_addon.py <mod_id>
python3 tools/lint_addon.py --cross
```

`--cross` без `mod_id` смотрит все моды в `addon/`: новый мод может патчить ту же секцию в том же пути, что уже существующий (`CROSS-001`). Один `mod_id` для перекрёстной проверки недостаточен.

```
Этап 5. Ответь по пунктам:
- список функций, помеченных UNVERIFIED, и как их проверить в игре;
- что будет, если поставить мод на существующий сейв;
- что будет, если снять мод с сейва, где он уже отработал;
- что сломается, если у игрока нет MCM.
```

## Этап 6. Упаковка

```bash
python3 tools/build_addon.py <mod_id> --zip
```

`CHANGELOG.md` заполняется в том же коммите: что добавлено, зачем, что не затронуто, версия сборки, на которой проверялось.

## Версионирование

Каждая версия мода — отдельная папка в MO2, а не перезапись предыдущей. Так откат — это галочка в менеджере, а не восстановление файлов. Подробнее: [`../mo2.md`](../mo2.md).
