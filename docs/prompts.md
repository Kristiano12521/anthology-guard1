# Готовые промпты

Копируются как есть. Общий принцип: в первом сообщении явно называем workflow и явно ограничиваем этап. Правила `workflow-*` подключаются агентом по описанию, но явное упоминание надёжнее автодетекта.

## Разбор вылета

```bash
python3 tools/xraylog.py logs/xray_<user>.log --out logs/card.md
```

```
Это разбор вылета, веди по workflow-crash. Этапы 1-3, ничего не исправляй.

@logs/card.md

Что менялось перед вылетом: <новый мод / правка / ничего>
Когда вылетает: <старт / загрузка сейва / конкретное действие>
Воспроизводится: <да/нет, как>

Дай: класс ошибки, первопричину с путём и строкой в reference/,
и чей это файл — ванилла, Anthology, сторонний аддон или мой мод.
```

Продолжение, когда причина названа:

```
Причина подтверждена. Этап 5: минимальный фикс с защитой в точке отказа.
API не меняем, функцию целиком не переписываем.
```

Если причина не подтвердилась:

```
Причина не подтверждена. Этап 4: диагностический скрипт,
который только логирует состояние через printf с тегом.
Скажи заранее, что я увижу в логе при каждом варианте гипотезы.
```

## Фикс бага

```
Это фикс, веди по workflow-fix. Этап 1, ничего не редактируй.

Симптом: <что видно в игре, при каких условиях>
Не проявляется: <когда работает нормально>

Найди в reference/ файл и функцию, отвечающие за это поведение.
Пути и номера строк. Несколько кандидатов — перечисли все.
```

```
Этап 2. Объясни механику словами: что происходит сейчас,
что должно происходить, в какой строке расходится.
Догадки помечай как догадки.
```

```
Этап 3. Все места вызова этой функции. Плюс: участвует ли значение
в сохраняемом состоянии, переопределяет ли функцию какой-нибудь мод сборки.
```

```
Этап 4. Минимальный фикс в 2-3 предложениях: способ, файлы,
и явно — что НЕ меняется. Кода не пиши.
```

```
Этап 5. Реализуй в addon/<mod_id>/.
```

## Новый аддон

```
Это новый аддон, веди по workflow-addon. Этап 1, файлов не создавай.

Что хочу: <механика с точки зрения игрока, 2-3 предложения>

Найди в reference/ и в аддонах сборки 1-3 примера, где сделано похожее.
Пути и краткое описание подхода. Если механика уже существует — скажи прямо.
```

```
Этап 2. Таблица: файл -> создаётся/патчится -> назначение.
Плюс: движковые функции (проверенные через refindex), что уходит в сейв,
что уходит в MCM, зависимости от других модов. Кода не пиши.
```

```
План принят с изменениями: <...>. Этап 4, реализуй.
```

## Проверка API

```
Проверь, существует ли <функция> в этой сборке.
Используй tools/refindex.py. Если нет определения — найди рабочий пример вызова.
Если нет и его — скажи прямо, что не подтверждено, и предложи способ проверки.
Не пиши код, пока не ответишь на это.
```

## Ревью чужого мода перед установкой

```
Разбери мод в reference/addons/<name>: что он патчит, какие файлы
заменяет целиком, есть ли пересечения с моими модами в addon/.
Оцени риск конфликта. Ничего не меняй.
```

## Когда агент не слушается

Пропустил этап и сразу выдал код:

```
Ты пропустил этап 1. Верни только список файлов и строк, без кода.
```

Уверенно использует незнакомую функцию:

```
Ты используешь <функция>. Покажи её определение в reference/
или пометь как UNVERIFIED. Если определения нет — предложи альтернативу,
которая точно есть в сборке.
```

Переписал больше, чем нужно:

```
Правка слишком широкая. Верни минимальный вариант: только строки,
без которых баг не чинится. Перечисли, что откатил.
```

Предлагает переустановку вместо диагностики:

```
Переустановка и удаление gamedata — не варианты, сборка в MO2 и моды мои.
Вернись к анализу лога.
```
