# Проверка движкового API

Самое ценное правило проекта. X-Ray документирован плохо, а модель охотно достраивает недостающее: код выглядит правдоподобно, компилируется в голове и падает в игре. Стоимость ошибки здесь — запуск игры и разбор лога, поэтому проверка окупается почти всегда.

## Как выглядит галлюцинация

```lua
-- Выглядит нормально. Такой функции может не существовать.
level.add_callback(level.game_start, function()
    ...
end)
```

Признаки: «логичное» имя функции, аккуратная сигнатура, отсутствие в `reference/`, уверенный тон без ссылки на источник.

## Протокол

```bash
# определение функции и места вызова
python3 tools/refindex.py find actor_on_first_update

# существует ли LTX-секция
python3 tools/refindex.py section wpn_ak74

# реально ли диспатчится такой callback
python3 tools/refindex.py callback actor_on_item_use

# что вообще есть в индексе
python3 tools/refindex.py stats
```

Нет попаданий — ищем рабочий пример вызова в `reference/` или в аддонах сборки. Нет и его — функция считается неподтверждённой.

## Порядок источников истины

1. `reference/` — исходники именно этой сборки.
2. Рабочие аддоны для Anomaly 1.5.3, уже стоящие в сборке.
3. README Modded Exes — там описаны функции, которых нет в ванилле.
4. Вики и гайды по Anomaly.
5. Форумы, ModDB, GitHub.
6. Память модели — источником не является.

Отдельная ловушка: код из гайдов по Call of Chernobyl, Call of Misery, OGSR, IX-Ray или чистому CoP может не работать в Anomaly 1.5.3. Совпадение имени функции ничего не гарантирует.

## Что делать при отсутствии подтверждения

Не выкидывать вариант, а помечать:

```lua
-- UNVERIFIED: нет определения в reference/, проверить в игре через printf
local ok = some_module.maybe_exists and some_module.maybe_exists(obj)
```

И в ответе явно: «функция не подтверждена, проверяется так-то». Требование к агенту — не молчать про неуверенность, а выносить её наружу.

## Быстрая проверка в игре

Если grep не дал ответа, первый шаг — `run_string` в уже запущенной сессии, без правки файлов. Команда есть в Modded Exes (`CCC_ScriptCommand` в `console_commands.cpp`) и регистрируется только с `-dbg`. Без ключа консоль ответит unknown command.

```
run_string printf("[mymod] some_module.maybe_exists = %s", tostring(some_module.maybe_exists))
flush
```

Появилось `nil` — функции нет. `printf` без `-dbg` в release тоже молчит (`vscript_log` в `script_storage.cpp`). `flush` (`CCC_FlushLog`) от `-dbg` не зависит; без него строка часто видна только в `.bkp` следующей сессии.

Диагностический скрипт (`<mod_id>_diag.script`, только `printf` с тегом) — для повторяющихся проверок: один и тот же снимок на каждом тике, на загрузке сейва, в бою. Одноразовый вопрос «есть ли эта функция» им решать дороже, чем `run_string`.

## Сигнатуры

Найденная функция ещё не означает известные параметры. Если параметры неясны — смотреть определение и один реальный вызов из `reference/`, а не догадываться по имени. `refindex.py find` выводит и то, и другое.
