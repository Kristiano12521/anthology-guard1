# Seamless Inventory Sort / Anthology 2.1 — правки

## [1.5.4] — 2026-08-28

**Изменено**

- `gamedata/scripts/trade_ui_profiler.script` — стойкая подсветка в торговле; диагностические обёртки ставятся по требованию
- `gamedata/scripts/seamless_inventory_sort_anthology.script` — fingerprint контейнера, кэш Antifreeze API, меньше движковых вызовов в `soft_resort`
- `gamedata/scripts/inventory_antifreeze_anthology.script` — именованные поля вместо позиционного списка с дыркой
- `gamedata/scripts/tooltip_control.script` — парный `on_game_end`

**Причина**

1. `trade_fast_unhighlight` (включена по умолчанию) гасила стойкую подсветку в окне торговли. `rax_persistent_highlight` перехватывает `UICellItem:Highlight` и рисует тинт favorite / junk / «новый лут» **в ветке `state == false`**, а `UICellItem:Set` подсветку не трогает вовсе. То есть покадровый полный обход в `UIInventory:UnHighlight_All` — единственное, что вообще красит стойкий тинт на свежесозданной ячейке. Разреженная замена вызывала `Highlight(false)` только для ячеек, ранее подсвеченных с `state = true`, поэтому ячейки только со стойким цветом не перекрашивались никогда.

2. `scan_container` считал `h = h + id + indx * 1000003`. Сумма симметрична: при перестановке двух предметов местами она не меняется, и `handle_now` / `request_handle` решали, что контейнер не тронут.

3. `af_module()` делал `pcall(mod.get_api)` на каждый вызов. Он дёргается из `af_busy()` → `can_soft()`, то есть по нескольку раз за refresh и дважды по четырём контейнерам в `resort_all_shown`.

4. Профайлер ставил обёртки на `UICellContainer:Update` и `UIInfoItem:Update` (оба покадровые, на каждый показанный контейнер) безусловно, при том что `trade_diag_enabled` по умолчанию выключен.

5. `af_items_data[i] = { obj, nil, tf and tf[i] }` — массив с дыркой на индексе 2; результат `#` на таких таблицах, а значит и `unpack`, спецификацией не определён.

**Как исправлено**

Полная замена четырёх скриптов оригинального мода (monkey-patch поверх них невозможен: правки лежат внутри локальных функций и замыканий `install()` / `patch()`, недоступных снаружи namespace).

- Подсветка: полный обход остался, но выполняется по интервалу (100 мс) вместо каждого кадра, а между полными проходами гасятся только реально подсвеченные ячейки. Набор отслеживаемых ячеек теперь ключуется по фактическому `hl:IsShown()` после вызова оригинала, а не по запрошенному `state`, поэтому ячейка со стойким тинтом остаётся в наборе и продолжает перекрашиваться.
- Fingerprint: `h = h + id * (indx + 1000003)` — по-прежнему не зависит от порядка `pairs`, но зависит от того, какому id достался какой индекс. Произведения остаются далеко внутри точного целочисленного диапазона double при реальных величинах id и индексов.
- Antifreeze API резолвится один раз и кэшируется; результат фиксируется в `on_game_start`, когда все скрипты уже загружены.
- Диагностические обёртки вынесены в `install_diag()`, который вызывается из `refresh_opts` при первом включении `trade_diag_enabled` и только после того, как отработал основной `install()` (чтобы сохранить свойство «патчим снаружи чужих обёрток»). Постоянно висят только `ci.Highlight` и `UnHighlight_All`.
- `af_items_data` хранит `{ obj = , sec = , info = }`, вызов стал `ORIG.AddItem(self, data.obj, data.sec, data.info)`.
- В `soft_resort` `section()` и `id()` берутся из таблиц, заполненных при первом обходе, вместо повторных движковых вызовов в цикле размещения.
- Во все четыре скрипта добавлен `on_game_end` с парными `UnregisterScriptCallback`. Это обычный callback, а не авто-вызываемая точка входа (в отличие от `on_game_start`), поэтому он регистрируется явно — как в `xrs_dyn_music.script` сборки.

**Не затронуто**

- Логика сортировки, батчинг, anti-oscillation, LTT / body_mode, ammo_parts, slot guard, disassembly window — без изменений
- `tooltip_control_utils.script`, `tooltip_fixes.script`, MCM-страница, тексты, текстуры — не менялись, берутся из оригинального мода
- Метрика `unhighlight_full` добавлена в отчёт профайлера, состав остальных метрик прежний
