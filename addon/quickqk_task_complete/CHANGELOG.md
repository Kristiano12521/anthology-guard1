# QuickQK Task Status Tool

## [1.4.1] — 2026-08-29

**Изменено**

- Конфликт одинаковых клавиш выполнения и провала: если обе стоят на E, провал больше не «восстанавливается» в ту же E. Свободная клавиша записывается в MCM.
- Состояние хоткея и подтверждения сбрасывается на `on_game_load`. Обработчики снимаются в `on_game_end`.
- В xray.log пишется заголовок из КПК (`current_title` / `CGameTask:get_title()`), а не ключ из `tm_*.ltx`.
- Скрипты без `zzzzzz_`-префикса. Списки клавиш в MCM не дублируются.

**Причина**

В 1.4 при complete=E и fail=E сброс провала на дефолт E ничего не менял. Состояние chord/confirm жило между сейвами. Лог для диагностики часто показывал LTX-ключ вместо названия в КПК.

**Не затронуто**

- MCM id `quickqk` и пути опций — сохранённые настройки игрока не сбрасываются
- Способ закрытия: `task_manager.set_task_completed` / `set_task_failed`
- Награда из диалога по-прежнему не выдаётся вне разговора

**Совместимость**

- Anomaly 1.5.3 / Anthology 2.1 / Modded Exes MT
- Сейвы: без миграции, своего `save_state` нет
- В MO2 выключить предыдущие QuickQK и копию из сборки `[GFX] QuickQK Task Status Tool Anthology`

**Проверено**

- lint: `python tools/lint_addon.py quickqk_task_complete`
- В игре: не прогонялось. Ожидается: F7+Q / F7+E закрывают отслеживаемое задание; при двух одинаковых клавишах провал уходит на свободную и сохраняется в MCM.
